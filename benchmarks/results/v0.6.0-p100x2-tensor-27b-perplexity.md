# v0.6.0 on 2x P100 — output identity of the internal AllReduce

The first `-npl`-class number in this repo, produced by
[`../ppl.sh`](../ppl.sh) on 2026-10-11. It exists because patch 49 is on by default for
pre-Volta cards, and the throughput rows in [the README](../../README.md) cannot tell a fast
reduction from a wrong one.

Machine `x99dual`: 2x Tesla P100-PCIE-16GB, build line `d81235049 (11429)` = llama.cpp `v0.6.0`,
44-patch tree. Model `Qwen3.8-27B-Q4_0` (14.94 GiB, 27.32 B params, dense). Corpus
`wikitext-2-raw/wiki.test.raw` (1,290,590 bytes) fetched with `scripts/get-wikitext-2.sh`; 8 chunks
of `-c 2048` = 16,384 tokens scored. `-fa on -t 28 -ngl 99`, one binary, four arms, two ubatch sizes.
Perplexity is deterministic, so no interleaving and no cooling were needed - unlike the throughput
runs, a difference here cannot be the weather.

The `±` is `llama-perplexity`'s own 95% CI over the corpus, so it is large relative to every
difference in the table: on the absolute scale none of these eight numbers is distinguishable from
any other. What makes the comparison meaningful is that all arms score the **same tokens in the same
order from the same binary**, so the differences are paired.

## Reading it

**Nothing here is the failure mode the check exists for.** qr0n's own record of a wrong AllReduce is
perplexity **7.68 where 3.53 belonged** - a 2x-scale error, not a 0.3% one. The widest gap in this
table is 0.024 PPL (0.46%), and the sign of the difference flips with the ubatch: at `-ub 512` the
internal path reads *higher* than the fallback, at `-ub 2048` *lower*. A broken reduction has a
direction; this is rounding.

**On both ubatch sizes the internal path is closer to the no-reduction control than the fallback
is** (0.0014 against 0.0178, then 0.0060 against 0.0176). The control is not ground truth - a layer
split changes the batch layout on each card, so it brings its own rounding - but it is the arm where
no cross-device sum happens at all, and both candidate reductions land inside 0.02 of it.

**The second H2D stream is invisible in the output**, which is what a pure scheduling change should
do: `tensor-h2d` reproduces `tensor-default` to the last printed digit at both ubatch sizes. That is
consistent with the ordering edge being present, and it is not proof. A missing edge is a race, and a
race shows up intermittently; one clean run per ubatch cannot exclude it. The claim this file makes
about patch 49's gate is therefore measured; the claim about its stream is not.

## What this does not cover

- **One model, dense, Q4_0, 16k tokens.** The 35B-A3B MoE was not scored, no tensor-split model with
  a `bf16` wire at a different context length was, and no F16/BF16 input type was (the internal path
  accepts F32/F16/BF16 and this run exercised the F32-with-BF16-wire branch, which is the one
  `GGML_CUDA_AR_BF16_THRESHOLD` controls).
- **No logit-level comparison.** The repo's standard is worse than this: `-npl` per token, or a
  top-k log-probability diff against the same build with the variable unset, would show where the
  0.02 comes from instead of only that it is small. `ppl.sh` prints one number per arm.
- **No repeatability across sessions** - each arm ran once. Perplexity is deterministic for a fixed
  `-ub` and corpus, so this is a low risk, but the throughput rows beside it are not.
- **The N-device half of patch 49** (`GGML_CUDA_AR_NGPU`) is untested here: two cards cannot exercise
  the slice arithmetic or the arrival-ring indexing at N > 2.

## Verdict this was asked to support

Patch 49's Pascal gate went **on by default** on the strength of this table: the internal reduction
is statistically indistinguishable from both the fallback and the no-reduction control, and it is
worth +13.6% prefill / +45.5% decode on the tensor split (see
[`v0.6.0-p100x2-tensor-27b-ar49on-summary.md`](v0.6.0-p100x2-tensor-27b-ar49on-summary.md)). `GGML_CUDA_AR_H2D_STREAM` and `GGML_CUDA_AR_NGPU` stayed off. The opt-out is
`GGML_CUDA_AR_PASCAL=0`, and it still works: rerunning `ppl.sh` on the rebuilt binary with the
variable unset reproduces `tensor-default` exactly (5.2524 / 5.2487) and with `=0` reproduces
`tensor-optout` exactly (5.2360 / 5.2603), with the init-failure warning present only in the second
case. Throughput follows the same switch: `tg128` 33.89 by default, 30.12 with `=0`, against 33.86
and 30.07 when the same two paths were selected by env var on the previous build.
